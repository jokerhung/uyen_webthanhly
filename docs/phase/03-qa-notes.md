## Ghi chú triển khai trước phiên kiểm tra

Code cho form ký gửi nhiều món, endpoint multipart, storage ảnh private và schema PostgreSQL đã được tạo. Luồng thu mua online mở `/buy/submit`, dùng chung form nhưng gửi `intakeType=buy`; ký gửi gửi `intakeType=consign`. DB lưu enum `consignments.intake_type`; phiếu thu mua mới chỉ chờ shop kiểm tra/báo giá, không tự thanh toán hoặc xuất bản hàng bán. Trường loại mặt hàng là combobox đọc lựa chọn đang hoạt động từ bảng `item_categories`; API chỉ nhận slug còn hiệu lực và DB ràng buộc foreign key. Xem `docs/database.md` về migration danh mục, dữ liệu khởi tạo và giá trị cũ. **Tiếp nhận khách thật hiện bị khóa chủ động**: `PRIVACY_POLICY_REVIEWED=false` hoặc thiếu giới hạn cấu hình trả 503 và biểu mẫu disabled. Không đổi cờ thành true chỉ để demo cho khách thật. Chủ shop cần phê duyệt chính sách xử lý/lưu/xóa thông tin và ảnh, tối thiểu/tối đa số món, số lượng/dung lượng ảnh, số hotline, nơi lưu trữ và backup, trước khi bật. Chưa có trang chính sách pháp lý chính thức.

API `POST /api/consignments`: `multipart/form-data`, header `Idempotency-Key` ngẫu nhiên 16–128 ký tự; fields `name`, `phone`, `consent=true`, `items` JSON, `images.0`, `images.1` ... ứng với index mặt hàng; chỉ nhận ảnh JPEG/PNG/WebP đúng magic/MIME, decode/rotate/resize/reencode WebP bằng sharp (loại metadata EXIF). Ảnh pending là tệp private không có route tải công khai; DB lưu key ngẫu nhiên. Mỗi phiếu ghi tên/số đã chuẩn hóa, items `pending`, ảnh và khóa idempotency trong một transaction, trả `{public_code,pending:true}`. Upload được dọn nếu DB lỗi. Hash payload với ảnh để retry cùng key không tạo phiếu trùng; khóa dùng lại với payload khác trả 409. Giới hạn tổng request 55 MiB, theo giờ dùng PostgreSQL shared bucket (5 attempts/hour toàn hệ thống cho đến khi có trusted-proxy IP config). **Giới hạn toàn hệ thống quá chặt cho production thực; cần thay bằng rate limit per-client ở reverse proxy được tin cậy trước triển khai.**

Dev/staging: `npm run db:migrate` rồi `npm run db:generate`. `CONSIGNMENT_STORAGE_DIR` phải trỏ đến volume private bền vững ngoài `public/`, có backup và quyền truy cập; fallback `.private/consignments` chỉ dùng local. Nếu chuyển nhiều instance hoặc deploy ephemeral/serverless, thay filesystem bằng object storage private trước khi bật. Các migration mới: `20260924000000_intake_idempotency`, `20260924001000_intake_rate_limit`. Chính sách retention, xóa ảnh sau khi phiếu bị từ chối và cơ chế cleanup nếu file không xóa được cần xây trước production. Admin xem ảnh sẽ được phân quyền ở Phase 4; hiện không có public image API.

Đã chạy migration local từ schema Phase 1 thành công. Unit tests kiểm tra strict validation và magic/storage. E2E default xác nhận form/API bị chặn khi chưa duyệt. Test ghi DB thực bằng dữ liệu giả nằm trong `tests/e2e/consignment-flow.spec.ts` chỉ bật bằng `RUN_INTAKE_DB_E2E=1` trên **database riêng có thể xóa** và `PRIVACY_POLICY_REVIEWED=true`; không chạy trên DB thật. Đã chạy bài E2E ghi DB trên `webkygui_phase3_test` tạo riêng từ database trống: trả mã phiếu, tạo một item/ảnh `pending`, replay cùng key trả cùng mã, key cũ khác payload trả 409 và payload tiêm `approved` không tạo phiếu (pass). Database/ảnh test đã được xóa sau đó. Chưa có bài test cưỡng bức DB lỗi giữa upload và transaction để chứng minh rollback file trong thực tế; cần bổ sung. Tránh log PII, không lưu khách ở URL/localStorage.
