Build without touching project services: `docker build --platform linux/amd64 -f docker/minio/Dockerfile.mc -t webkygui/mc:77f82e18 docker/minio`. Run only the isolated smoke: `& ./docker/minio/smoke-mc.ps1` in PowerShell. The smoke creates a randomly named **internal** Docker network and a fresh `--rm` MinIO server from existing local `webkygui/minio:9e49d5e7` with no host ports, persistent mounts, or Compose-network attachment. It checks built client version and `mc ready`, then performs **read-only** `mc admin user list`; finally removes server/network. It never creates IAM identities, policies, or buckets. The `MC_HOST_smoke` environment variable embeds disposable credentials only; Docker inspect can expose them while the brief container runs. Use a secret manager and appropriately isolated hosts for real credentials; do not copy this approach into live operation.
